
## Why Telemetry Data Should Be Stored

Telemetry data storage is critical because it allows you to keep a historical record of a system's health and behavior over time. In complex systems such as satellites, space stations, or technology infrastructures, multiple sensors continuously generate information on critical variables such as temperature, battery level, signal strength, power consumption, and subsystem status. If this data were not stored, it would be impossible to analyze trends or identify gradual changes in the operation of the system. Historical logs allow engineers to detect anomalies, analyze performance patterns, and reconstruct events when a failure occurs. For example, if the temperature of a system increases progressively over several days, historical analysis can reveal a potential problem in the thermal control system before it becomes a critical failure. In the context of the Space Dogs project, storing telemetry also makes it possible to test monitoring algorithms, validate anomaly detection models, and evaluate the performance of automated systems, such as the incident response agent that analyzes the data generated by the API. In addition, telemetry logs can be used to improve future missions or systems, as they provide empirical evidence on the real or simulated behavior of subsystems.

## How spacecraft monitoring systems store telemetry historically
In real space missions, monitoring systems record telemetry data in a continuous, structured, and time-synchronized way. Each sensor or subsystem on the spacecraft sends periodic measurements that are transmitted to ground stations and stored in specialized databases. Each telemetry record includes key information such as the measured value, the sensor or subsystem identifier, the unit of measurement, and an accurate timestamp. This approach allows a detailed timeline of the spacecraft's behavior to be constructed throughout the mission. Engineers use these logs to analyze the performance of critical subsystems such as the power system, thermal control, navigation systems, and communications. In addition, historical analysis makes it possible to compare current behavior with previously recorded nominal conditions, making it easier to detect deviations or anomalies. In advanced systems, this data is integrated into monitoring platforms that apply data analysis, machine learning, and event correlation algorithms to identify potential problems before they impact the mission. In educational or experimental projects such as Space Dogs, this same concept is replicated by APIs that generate simulated telemetry and databases that store that data for later analysis.


 ## How SQLite simulates this concept in the project

In the project developed during the hackathon, SQLite is used as a lightweight database engine to store telemetry logs generated by the API. SQLite is an integrated database that does not require a separate server, making it ideal for experimental projects or prototypes of monitoring systems. Each time the API endpoint generates a set of telemetry data—including variables such as temperature, battery level, signal strength, subsystem status, and timestamp—these values can be saved as a new record within a table in the database. Over time, this table becomes a simulated telemetry chronological history, similar to the records that are generated in real space systems. This storage allows data to be consulted, trends to be analyzed, changes in variables to be visualized, and anomaly detection algorithms to be tested. Although the data is synthetically generated by random functions in the code, the process replicates the fundamental flow of a real telemetry system: data generation → transmission through an API → storage in a database → analysis and monitoring of the system. In this way, SQLite allows simulating a technical monitoring environment where system behaviors can be studied, performance metrics can be evaluated, and telemetry analysis tools can be developed within a simple software architecture.
